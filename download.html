First time on a Mac? Here’s how to open it.

Opening Signet7 on a Mac (first time)

Signet7 desktop for Mac is not signed with an Apple Developer ID certificate yet, and it is not notarized. macOS Gatekeeper is doing its job when it shows Signet7 Not Opened or says Apple could not verify the app is free of malware. That is normal for this early access build — not a sign that something is wrong with your download. Apple-signed builds are on the way; until then, use the steps below once on each Mac.

Why macOS stops the first launch

Apple checks apps from known developers before it lets them run without a prompt. Our Mac zip is unsigned while we finish that program, so your Mac asks you to confirm that you trust Signet7 on this computer. After you allow it once, later launches behave like any other app you installed yourself.

Recommended: System Settings (macOS 15 Sequoia and later)

On current macOS, including Sequoia, Apple expects you to approve unidentified apps in System Settings — not with Control-click → Open in the Finder. That right-click route worked on older macOS versions; on Sequoia and later it no longer bypasses Gatekeeper. Use Settings instead.

  1. Unzip the download from your company account. Move Signet7.app into Applications (drag it out of the zip folder so you are not running it from a read-only disk image or download folder).
  2. Double-click Signet7.app once. macOS shows the warning. Click Done (you may also see Move to Trash — do not use that).
  3. Open System Settings → Privacy & Security. Scroll to Security.
  4. Next to the message about Signet7 being blocked, click Open Anyway, confirm, and enter your Mac login password if asked.
  5. Open Signet7 again from Applications. It should launch normally from now on.

Apple’s steps match this flow: Open a Mac app from an unknown developer.

Older macOS (optional)

On macOS versions before Sequoia, some people used Control-click (or right-click) the app → Open → Open again in the dialog. That bypass is removed in Sequoia; if you are on an older release and prefer that habit, it may still work there — but System Settings is the reliable path on every supported version.

Advanced: Terminal

If you are comfortable with Terminal, you can remove the download quarantine flag Apple attaches to zips:

xattr -dr com.apple.quarantine /Applications/Signet7.app

Change the path if Signet7.app lives somewhere else — for example ~/Downloads/Signet7-Mac/Signet7/Signet7.app — then open the app from Applications when you can.

Troubleshooting

  • Open Anyway only appears for about an hour after macOS blocks the app. If the button is gone, double-click Signet7 again to refresh the Security entry, then return to Privacy & Security.
  • Run Signet7 from Applications, not from inside the zip or another read-only folder.
  • If your organization uses Mac admin tools or MDM that blocks unidentified developers, ask IT to allow Signet7 on the office computer that needs it.

Do you need a download?

Usually not. Here is every route.

The people receiving your email are not required to install anything — a thousand of them are covered because they can open the check in a browser. Signet7 desktop only ever covers the work addresses you name, on office computers.

Browser check — nothing to install

The route for everyone on the other side. verify.signet7.io/email/verify, no account. Upload the Signet7-sealed.eml attachment if there is one, otherwise the saved email. Or attach the saved original to check@signet7.io and the answer comes back by email.

Signet7 pane for Outlook — optional

Files are hosted at signet7.io/outlook. Save the manifest, open aka.ms/olksideload, and choose Add from File. It is not an AppSource listing, and the newer Apps area cannot upload XML. The Seal this draft button attaches Signet7-sealed.eml. That file is the letter. Do not send the Outlook draft.

Signet7 desktop — this page

One Windows or Mac computer per set of named addresses. Early access. Both jobs live in this app: checking what arrives, and optionally signing what you send through 127.0.0.1 port 2525. That hop seals the email itself.

Company account — no download

Sign in by email link at account.signet7.io/account. Registering is free.

Lab builds

A browser extension, a Gmail add-on, and an Android build exist as unpacked sideloads in the client tree. None of them is the product, and none is in a store.

Not in any app store

Signet7 is not published in any consumer or enterprise app marketplace. If you find something claiming to be Signet7 in one, it is not us. After you sign in, the file is on your company account. The pane files at signet7.io/outlook are the Outlook add-in.

For IT

Rolling this out

  1. Push the Signet7 pane for Outlook from Microsoft 365 admin → Settings → Integrated apps, assigning it to a group as Available, Optional, or Fixed. The pane files live at signet7.io/outlook. Steps: IT push to laptops.
  2. Do not push Signet7 desktop to every laptop. There is no Intune MSI yet, and Windows and Mac will show an extra warning until we finish signing the app. Install it only on the computers handling named addresses.
  3. Choose which work addresses can move money, jobs, or clients. Not every inbox. Register the app in Microsoft Entra; Graph consent still requires a person.
  4. Ordinary mail stays quiet, and quiet means it is working. On a named address, signing happens automatically over SMTP at 127.0.0.1 port 2525. See where the signature lives.
  5. Tell everyone else the one thing they need: if an email asks you to move money, upload it at verify.signet7.io/email/verify before acting.

It is the same on Windows and Mac. It is not Exchange, not a mail app, and not a spam filter — Outlook stays Outlook and Apple Mail stays Apple Mail. Worked examples: what a clerk actually does.
