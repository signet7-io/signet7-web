Product

A policy decision point between instruction and execution.

Signet7 connects supported cryptographic instruction evidence to the exact action an AI agent proposes. The current local candidate evaluates a narrow static policy, returns allow or block, and seals the decision record. The integrating caller enforces the result.

Current decision path

Six bounded steps. One explicit enforcement boundary.

1

Receive

A claimed sender, message ID, instruction body, exact proposed action, and optional signature/key evidence enter the gate.

2

Bind

An action-bound signature covers the sender, message identifier, body, and exact action.

3

VSN

The Verifiable Sender Network looks up whether that signing key is still bound to the domain or organization. Lookup is live on qual. Customer companies are not in it. Managed VSN enrollment is planned.

4

Evaluate

The action is normalized to a canonical family and checked against the current static policy.

5

Record

A tenant-scoped signed, hash-chained record preserves the allow/block decision.

6

Enforce

The caller refuses or performs the action. Signet7 does not perform the downstream execution.

Current contract: no separate inbound/outbound direction field, no customer-authored policy language, and no universal interception of agent tools.

Current high-risk families

Known actions can require bound identity. Unknown actions fail closed.

The current policy is intentionally narrow. It recognizes exact canonical identifiers rather than trying to infer arbitrary natural-language intent.

Consequential email

Email is the instruction layer people already rely on.

The current s7-email-1 candidate signs and verifies declared protected headers, supported MIME structure, text and HTML alternatives, and attachment bytes plus declared metadata. It can provide component-level results and a fact-only receipt.

Protected scope

The verifier reports what the signed profile covered. It does not claim every header, transform, provider, or undeclared component.

Sender/key evidence

A valid signature shows possession of the corresponding private key. A separately governed binding connects that key to the claimed sender.

Human checkpoint

People can inspect supported evidence before acting. A valid result does not mean the message is wise, lawful, malware-free, or safe.

Decision evidence

Preserve what the gate evaluated.

The source includes signed hash chains, detached export, offline verification, evidence bundles, retention-policy and hold events, recovery paths, and optional S3 Object Lock anchoring.

Source capability

  • Tenant-scoped signed decision chronology
  • Portable manifests, checksums, and bundle attestation
  • Separately controlled signer/head verification inputs
  • Optional external anchor path

Not implied

  • Complete original-input custody in every path
  • Universal seven-year retention
  • Active Object Lock in every deployment
  • Certification or legal admissibility

Planned Verifiable Sender Network (VSN)

Managed identity and key lifecycle at organizational scale.

VSN is intended to manage enrollment, status discovery, rotation, revocation, recovery, administration, scalable verification, abuse controls, monitoring, support, and service levels.

Foundation versus service

The current tenant trust registry, signing SDK, and optional DNS profile are real foundations. They are not the complete managed VSN service.
