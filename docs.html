Check an Email

Check if an email is authentic and hasn't been changed. No account or installation required.

1

Save the email file

If the email has a Signet7-sealed.eml attachment: Open and save that attachment file.

If there's no attachment: Save the entire email from your mail app (File → Save As).

2

Open verification tool

Go to verify.signet7.io/email/verify in any web browser.

3

Drop and verify

Drag the saved file onto the verification page. Results appear instantly - no waiting or processing time.

Understanding your results:

✅
Verified: The email is authentic and unchanged since it was signed.
⚠️
Not Verified: Either the email wasn't signed or has been modified.
❓
Unknown: Signature exists but sender identity can't be confirmed.

Sender verification: Listed, Not listed, or Listing doesn't match this address - these results help you understand sender authenticity.

Verification status: Matched, unmatched, or unknown.

Important: Signet7 tells you if an email has been tampered with, but doesn't tell you if the content is safe, authorized, or trustworthy. Always use your judgment when acting on email content.

Setup: Outlook on the Web

Add digital signing to Outlook on the web. Perfect for Microsoft 365 users who want browser-based email security.

⏱️ Setup time: ~10 minutes

Step 1: Create your Signet7 account

  1. Go to account.signet7.io/account
  2. Enter your work email address
  3. Click "Email a sign-in link"
  4. Check your email and click the link (or enter the 6-digit code)
  5. Copy your Signet7 token - you'll need this later

Step 2: Install the Signet7 Outlook pane

  1. Download the manifest file: signet7.io/outlook/manifest.xml
  2. In the same browser as Outlook, go to aka.ms/olksideload
  3. Click My add-ins → Custom Addins → Add a custom add-in → Add from File
  4. Select the downloaded manifest.xml file and click Install
  5. Reload Outlook on the web, then see Step 3 to sign an email

Step 3: Use Signet7 to sign emails

  1. Compose a new email in Outlook on the web
  2. Click Enhance Outlook with apps in the compose toolbar
  3. Select Signet7 from the apps list
  4. Paste your Signet7 token in the pane (this saves for future use)
  5. Click Sign and send email
  6. Wait until the pane says a signed copy is attached, then click the Send button in Outlook on the web

✅ You'll know it's working when:

  • You see "Sealed. A signed copy is attached" in the Signet7 pane
  • Your sent email includes a "Signet7-sealed.eml" attachment
  • Recipients can verify your emails at verify.signet7.io

Setup: Desktop Email Apps

Automatically sign all your outgoing emails from Outlook Desktop, Apple Mail, or Thunderbird.

⏱️ Setup time: ~20 minutes

Step 1: Create your account and get credentials

  1. Create your Signet7 account at account.signet7.io/account
  2. Copy your Signet7 token
  3. For Gmail users: Create a 16-letter app password at myaccount.google.com/apppasswords
  4. For Microsoft 365 users: Your IT team may need to set up Microsoft Entra integration

Step 2: Download and install Signet7 desktop

  1. Go to the Download page and get the desktop app
  2. Extract the zip file and run the Signet7 application
  3. Configure your email settings in the left panel
  4. Paste your Signet7 token and email credentials
  5. Click "Save and watch"
  6. Verify the footer shows "Listening on 127.0.0.1:2525"

Step 3: Configure your email client

For Outlook Desktop:

  1. Go to File → Account Settings → More Settings → Outgoing Server
  2. Set SMTP host to 127.0.0.1, port 2525
  3. Turn TLS/SSL off for this connection
  4. Send a test email

For Apple Mail:

  1. Add a new "Other Mail Account" (not Google account type)
  2. Set incoming to your normal email settings
  3. Set outgoing SMTP to 127.0.0.1:2525 with TLS off
  4. Send a test email from this account

For Thunderbird:

  1. Go to Account Settings → Outgoing Server → Add
  2. Set host to 127.0.0.1:2525 with TLS off
  3. Use this server for your work email account
  4. Send a test email

✅ You'll know it's working when:

  • Signet7 desktop shows "Listening on 127.0.0.1:2525"
  • Test emails are automatically signed (no attachment, email itself is signed)
  • Recipients can verify your emails by saving and dropping them on the verification tool

Set up your free account to start signing emails. No credit card required.

1

Visit account page

2

Enter work email

Use your business or work email address. Personal emails (Gmail, Yahoo, etc.) won't work for signing.

Verify and get token

Click the link in your email or enter the 6-digit code. Copy your Signet7 token for setup.

Important: Keep your Signet7 token secure. This is what signs your emails. If you lose it, create a new sender token from the account desk (see Manage sender tokens). The desk never shows a token value again after it is created.

Manage sender tokens

Sender tokens are the secrets that sign your outgoing mail. Each Signet7 account can hold multiple tokens so different people or devices can seal without sharing one password-like string.

Account owner only: Only the account owner can create sender tokens, mark a token for deactivation, or permanently delete a deactivated token. Other users on the account can still paste an active token into the Signet7 Outlook pane or desktop app if the owner shared it with them through your normal internal process.

How many tokens you can have

By default up to five sender tokens are allowed per account. If you need more, email support@signet7.io and Signet7 can raise the limit for your account.

Create a sender token

1

Open the account desk

Sign in at account.signet7.io/account as the account owner. Open Account overview (or the Tokens area on that page).

2

Create and label

Choose to create a new sender token. Add an optional label (for example Outlook laptop — Alex). If you skip a label, the desk shows a short fingerprint so you can tell tokens apart later.

3

Save the token from email

Signet7 emails the raw token once to the owner. Copy it from that message and store it somewhere safe. The account desk never displays the full token again.

Use the token in Outlook or desktop

  1. Outlook on the web: Open the Signet7 Outlook pane while you compose mail and paste the token into the token field. The pane saves it for later messages on that browser.
  2. Desktop Signet7: Paste the same token into the Signet7 Token field in the desktop app on each computer that should seal with that token.

Every active token can seal mail until you mark it for deactivation. You can run more than one active token at the same time (for example one per device or team member).

Mark a token for deactivation

When a token should stop signing, the owner marks it for deactivation in the account desk. Sealing with that token stops immediately—there is no grace period where old copies still work.

Before you mark a token: Update every Outlook pane and desktop install that still uses that token. Point them at another active token, or create a new one first. Any device still holding the old token will no longer seal until you paste a different active token.

Permanently delete a token

After a token is marked for deactivation, the owner must wait seven days. Then the desk lets the owner permanently delete that token record. Deletion is final; you cannot recover the token value or reuse the same secret.

Audit

Signet7 records when sender tokens are created, marked for deactivation, and deleted. That history supports security review on your side. It is not a separate product you configure in these docs—your account activity reflects those events.

Need a higher token limit? Contact support@signet7.io from the account owner address.

How It Works

Understanding the technology behind Signet7's email security.

🔏 Digital Signatures

Signet7 creates a cryptographic signature for each email that proves authenticity and detects tampering.

🔗 Sender Verification

Recipients can verify that emails actually came from the claimed sender and haven't been modified.

🛡️ Tamper Detection

Any changes to the email content, subject, or attachments after signing will be detected during verification.

Two signing methods:

Outlook Pane Method

  • Creates a Signet7-sealed.eml attachment
  • Original email remains unsigned
  • Recipients verify the attachment file
  • Works in web browsers

Desktop App Method

  • Signs the entire email message
  • No separate attachment needed
  • Recipients verify the email itself
  • Requires local software

Troubleshooting

Common issues and solutions for Signet7 setup and usage.

❌ Outlook pane not appearing

  • Check if manifest.xml was uploaded correctly
  • Try refreshing Outlook on the web
  • Verify your mailbox supports custom add-ins
  • Use aka.ms/olksideload for sideloading

⚠️ Emails not being signed

  • Confirm you clicked "Sign and send email" before Send
  • Check that your Signet7 token is valid
  • For desktop: verify "Listening on 127.0.0.1:2525" appears
  • Make sure SMTP is configured correctly

🔍 Verification failing

  • For pane method: verify the Signet7-sealed.eml attachment
  • For desktop method: save and verify the entire email
  • Check that the email hasn't been forwarded or modified
  • Ensure you're using the correct file type

🔐 Token or account issues

  • Get a fresh token from account.signet7.io
  • Verify your work email address is correct
  • Check if your token has expired (90-day trial period)
  • Contact support for account-related issues

Agents & API integration

Who this is for: builders connecting Signet7 to agents, workflows, or APIs — not end users sealing or checking mail in Outlook.

What it’s for: before your system acts on an email (especially money moves), call Signet7’s API, get allow or refuse, and honor that answer.

Public product shape lives on Product. Trust language is on Trust. Privacy, security, and retention are on Trust center.

Signatures cover both authenticity and the action the email is asking for (for example pay or transfer). If Signet7 doesn’t recognize that action, it says do not proceed. There is no separate inbound/outbound direction field.

Your systems call Signet7’s API over HTTP or MCP. Signet7 returns allow or refuse; your system must follow that. Treating the answer as a hint and executing anyway defeats the point.

To check an email, submit the original message bytes (text and HTML parts, attachments, and headers) as email candidate s7-email-1 — don’t rebuild From, To, Subject, or body.

Helper instruction card

Do not train a model on company mail. Do not rebuild From, To, Subject, or body. Save the original message file. Submit those bytes to the check page. Read two facts: seal, and listing. If the check is down, do not act. Recipients are not required to install. Company computers use the desktop zip, not pip. This card is instructions, not a plugin.

Current Status and Limitations

Early access status: App signing is not finished yet — not Authenticode. The desktop helper cryptographically seals that exact message, and this is not Authenticode signing. Domain-wide is a choice, covering specific addresses assigned to it rather than every possible mailbox automatically.
